# TriggerLab v0.3.2 — локальный FPS-тренажёр

Учебный стенд на C++20 для Windows x64. Движущаяся мишень, прицел, BGRA-буфер и симулированные выстрелы работают внутри приложения. Доступа к сторонним играм и отправки системного ввода нет.

## Сборка и проверка

Требования: Visual Studio 2022 / Build Tools с Desktop Development with C++, Windows SDK, CMake 3.20+.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\TriggerLab.exe
```

Если CMake отсутствует в PATH, используйте `& 'C:\Program Files\CMake\bin\cmake.exe'` и аналогичный путь к `ctest.exe`. `build-windows.bat` выполняет сборку, тесты и запуск.

В VS Code откройте `C:\TriggerLab`, установите расширения Microsoft C/C++ и CMake Tools. Выполните **CMake: Configure** с Visual Studio 2022 x64, выберите Release через **CMake: Select Variant**, затем **CMake: Build** и **CMake: Run Tests**. Команды выше также работают во встроенном PowerShell-терминале.

## Управление и диагностика

| Управление | Действие |
|---|---|
| SPACE (удерживать, фокус на сцене) | Активировать детектор |
| ↑ / ↓ | Cooldown ±25 мс |
| ← / → | Радиус ROI ±1 px |
| R | Сбросить статистику и позицию мишени |
| ESC (фокус на сцене) | Закрыть окно |
| Apply and save | Проверить все поля, применить и сохранить |
| Reset statistics / scene | Сбросить счётчик и сцену |
| Tab / Shift+Tab | Переход между полями и кнопками |

Щелчок по сцене возвращает ей фокус. После применения и сброса фокус возвращается автоматически. Потеря фокуса снимает активацию. Панель показывает семь редактируемых параметров; на сцене отображаются FPS, состояние автомата, активность, покрытие ROI, обнаружение, cooldown, стабильность и счётчик. Отрисовка остаётся Win32/GDI: для этих элементов интеграция Dear ImGui/DX11 не требуется. Дополнительных пакетов нет. Приложение использует один UI-поток; при закрытии удаляется таймер, GDI-объекты не накапливаются.

## Настройки JSON

Путь: `%LOCALAPPDATA%\TriggerLab\settings.json`; если LOCALAPPDATA недоступен — `settings.json` в текущем каталоге. Файл создаётся при применении настроек или изменении cooldown/ROI клавишами. Статус загрузки/сохранения отображается внизу сцены; ошибки не закрывают приложение.

```json
{
  "cooldown_ms": 180,
  "roi_radius": 5,
  "stable_frames": 2,
  "minimum_coverage": 0.45,
  "minimum_red": 160,
  "minimum_blue": 150,
  "maximum_green": 130,
  "scene_profile": 0,
  "scene_speed": 1,
  "language": 1
}
```

Диапазоны: cooldown 50–2000 мс, ROI 0–30 px, подтверждение 1–20 кадров, покрытие 0.01–1, цветовые каналы 0–255. Для целочисленных параметров дробные значения запрещены. Принимаются семь полей v0.2 или девять полей v0.3, а также необязательное поле language версии v0.3.2 (scene_profile и scene_speed присутствуют вместе): пропущенные, неизвестные, повторяющиеся поля и лишний текст отвергаются. Размер ограничен 64 KiB. Отсутствующий, нечитаемый или повреждённый файл возвращает все значения по умолчанию. Неверные поля панели оставляют действующие настройки без изменений.

Запись сначала идёт в соседний `settings.json.tmp`; после успешной записи, flush и close Windows заменяет основной файл через MoveFileExW. При ошибке записи предыдущий файл сохраняется. Ошибка сохранения не отменяет уже применённые настройки в памяти. Не запускайте несколько экземпляров с одновременной записью одного файла.

## Тесты и архитектура

`Config.hpp` / `Config.cpp` содержат переносимую сериализацию, проверку схемы и файловое сохранение. Остальное ядро: Frame, Simulation, TargetDetector, TriggerEngine. UI находится в `src/win32/main.cpp`.

CTest запускает существующие тесты ядра, тесты JSON (границы, типы, повреждения, round trip, чтение и сохранность файла при ошибке записи) и Windows smoke-тест. Последний создаёт скрытое настоящее окно, проверяет поля, отрисовку, обнаружение, активацию/снятие активности, сохранение, отклонение неверного ввода и сброс, затем закрывает окно. Это автоматическая проверка, визуальная оценка внешнего вида выполняется отдельно. Smoke-тест сохраняет данные во временный каталог и удаляет его; пользовательский конфиг не меняет.

На Linux/macOS доступны ядро и два тестовых набора без GUI:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## GitHub

В репозитории находятся только исходники, тесты и документация. Сборки, пользовательские настройки и локальный `codex_handoff.json` исключены через `.gitignore`; handoff остаётся в рабочем каталоге как историческая передача v0.1.

Workflow `.github/workflows/ci.yml` запускается при push, pull request или вручную: Windows 2022 собирает MSVC Release x64 и запускает четыре теста; Ubuntu 24.04 проверяет переносимое ядро. После успешного Windows job исполняемый файл доступен как артефакт `TriggerLab-windows-x64`. Первое выполнение GitHub Actions проверяется после загрузки репозитория.

Для первой загрузки создайте пустой репозиторий TriggerLab на GitHub без автоматически созданных README, .gitignore и LICENSE. В терминале проекта выполните:

```powershell
git remote add origin https://github.com/YOUR_LOGIN/TriggerLab.git
git push -u origin main
```

Замените `YOUR_LOGIN` своим логином. Если Git не находится в PATH, используйте Git Bash или добавьте установленный Git в PATH. Лицензия выбирается владельцем отдельно перед открытой публикацией.


## Новое в v0.3

Сцены: Crossing сохраняет классическую мишень, Multiple targets показывает три мишени с разными фазами движения, Precision уменьшает размер мишени. Выберите сцену и скорость 0.25–3, затем нажмите Apply scene and save. При изменении сцены сбрасываются позиция, счётчик и диагностика. В JSON scene_profile: 0 = Crossing, 1 = Multiple, 2 = Precision. Старые файлы v0.2 загружаются с классической сценой и скоростью 1.

P или Pause scene останавливает движение и снимает активацию; SPACE на паузе не вызывает выстрелов. R сохраняет выбранный профиль и скорость, сбрасывая сцену и статистику.

P50/P95 вычисляются методом ближайшего ранга по последним 2048 выстрелам. Один образец — время от первого кадра обнаружения при активном детекторе до выстрела; после выстрела отсчёт начинается с следующего кадра, при потере цели или снятии активности прерывается. Повторные измерения могут включать ожидание cooldown. Это время внутренней симуляции с учётом кадров UI, а не задержка системного ввода. До первого образца отображается --.

Журнал содержит последние 4096 изменений состояния, активности, видимости и выстрелов; три последних события видны в окне. Export event log (CSV) записывает events.csv рядом с settings.json, заменяя прошлый экспорт. Колонки: elapsed_ms, active, target_visible, state, fired, shots. State: 0 Idle, 1 Armed, 2 Detected, 3 Cooldown. Экспорт выполняется только по кнопке. Сброс очищает журнал и метрики.

Тесты session_tests проверяют сцены, скорость, сброс, P50/P95, потерю цели, CSV и ограничения памяти. Windows smoke-тест дополнительно проверяет паузу, сохранение профиля и экспорт.


## Исправление отрисовки и мышь (v0.3.1)

Отрисовка использует повторно используемый GDI back buffer: сцена и текст рисуются вне экрана, затем готовый кадр переносится одним BitBlt. Таймер обновляет только область сцены, а WS_CLIPCHILDREN защищает панель настроек от перерисовки родительским окном. Буфер пересоздаётся только при изменении размера, GDI-объекты освобождаются при выходе.

- Движение мыши по сцене перемещает прицел и ROI детектора.
- Удержание ЛКМ активирует симулированный триггер; SPACE остаётся альтернативой.
- Отпускание ЛКМ, выход указателя за сцену, потеря захвата/фокуса и пауза снимают активацию мышью. При захваченном перетаскивании возврат на сцену снова активирует удерживаемую ЛКМ. SPACE действует независимо.
- ПКМ и сброс R возвращают прицел в центр; кнопки панели не активируют триггер.
- На паузе выстрелов нет. Все действия остаются внутри собственного окна.

Smoke-тест проверяет мышь, детекцию по координатам прицела и отсутствие роста числа GDI-объектов после 100 перерисовок с изменением размера буфера.


## Язык интерфейса (v0.3.2)

Внизу панели настроек есть отдельный список «Язык / Language»: Русский и English. Выбор сразу переводит кнопки, подписи, состояния, подсказки, названия сцен и сообщения, без перезапуска и сброса статистики. Не применённые значения полей сохраняются на экране. Язык автоматически записывается в settings.json: language = 0 для English, 1 для русского. Настройки предыдущих версий без этого поля используют русский по умолчанию. Если запись не удалась, сообщение отображается на выбранном языке, но выбор после перезапуска не гарантирован.

Формат CSV и JSON сохраняет стабильные английские имена полей для совместимости. Каталог переводов находится в include/triggerlab/Localization.hpp; исходники компилируются MSVC в UTF-8.

## Ветка screen-analyzer: M0–M2

В feature/screen-analyzer добавлены базовые компоненты реального read-only захвата и цветовой маски. Текущий тренажёр сохранён. Для ручной проверки соберите проект и запустите `build-m12\Release\TriggerLabCapturePreview.exe`: Start включает захват ROI у курсора, Stop или ESC выключают его, C выбирает цвет под курсором, H переключает RGB/HSV. Уведите курсор за окно preview, чтобы анализировать рабочий стол; чёрный ROI показывается с предупреждением. Полноценный основной интерфейс анализатора и миграция настроек ещё не реализованы.

Контракты API, базовые результаты и команды: [docs/screen-analyzer-m0-m2.md](docs/screen-analyzer-m0-m2.md).

## Выбор цвета и автоклик в анализаторе

Запускайте `build-color\Release\TriggerLabCapturePreview.exe` (итоговая локальная сборка этой функции).

1. Задайте R/G/B и допуск (0–255) и нажмите «Применить RGB», либо откройте «Выбрать цвет…».
2. Для цвета с экрана включите Start, нажмите «Пипетка (3 сек.)» и за три секунды наведите указатель на нужный пиксель за пределами окна анализатора. C — немедленный выбор при активном окне. При неуспешном захвате цвет не меняется.
3. Нажмите «Сохранить цвет». RGB и допуск записываются в `%LOCALAPPDATA%\TriggerLab\selected-color.json` с безопасной заменой файла. При перезапуске цвет восстанавливается. Сцена и прежний settings.json не изменяются; HSV-режим и разрешение автоклика не сохраняются.
4. Для автоклика нажмите «Выбрать окно (3 сек.)», активируйте нужное окно и разместите в нём указатель. Название выбранного окна видно внизу анализатора.
5. Вернитесь в анализатор, включите Start и отдельную галочку автоклика, затем активируйте выбранное окно. Клик выполняется, когда пиксель под курсором совпадает с цветом два последовательных кадра. Маска и покрытие показываются для диагностики; порог покрытия не ограничивает клик по самому пикселю.

Один непрерывный hover даёт один клик. Для следующего нужно уйти с цвета/целевого окна и навести заново; минимальный интервал 250 мс. Ошибочный захват не считается уходом с цвета. Указатель не перемещается автоматически. Перед вводом повторно проверяются окно под указателем, активное окно, процесс выбранного окна и свежие координаты. При зажатых Ctrl/Alt/Shift или кнопках мыши автоклик приостанавливается. Изменение цвета/режима снимает разрешение автоклика.

Stop, ESC в анализаторе и глобальная F9 отключают захват, отсроченную пипетку и автоклик. Если F9 занята другим приложением, автоклик не включается. При отказе SendInput автоклик выключается; приложения с повышенными правами могут отклонять ввод по [правилам UIPI Windows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput). Приложение не повышает права и не обходит ограничения.

Тесты проверяют JSON цвета, сохранность файла при ошибке, единичный клик на hover, повторное наведение, ошибки захвата, ограничения выбранного окна и кнопки Start/Stop. Автоматические тесты не отправляют клики в сторонние приложения; реальный ввод нужно проверять в выбранном пользователем окне.
