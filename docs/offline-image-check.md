# Проверка сохранённых изображений без тренажёра

`TriggerLabImageCheck.exe` — диагностическая утилита Windows из сборки с тестами. Она читает изображение через тот же WIC-декодер, что анализатор, вырезает указанную область и вызывает `aimColorMask`. Проверка RGB не открывает окна, не захватывает экран, не отправляет ввод и не меняет настройки. Утилита не входит в portable-архив приложения.

## Запуск

После обычной сборки Release из корня проекта:

```powershell
& .\build-release\Release\TriggerLabImageCheck.exe 'C:\Samples\target.png' 193 198 93 435 25
```

Порядок аргументов:

```text
TriggerLabImageCheck IMAGE R G B X Y [SIDE [TOLERANCE [IGNORE [PERCENT]]]]
```

`X/Y` — левый верхний угол области в исходном изображении, начало координат сверху слева. Значения по умолчанию: сторона 31, RGB-допуск 24, радиус исключения центра 3 (квадрат 7×7), порог 3%. Необязательные параметры задаются по порядку. Они проверяются по тем же ограничениям, что настройки анализатора. Область должна целиком помещаться в кадр; она не обрезается и не масштабируется. Для другой стороны области укажите совместимый радиус исключения.

Результат — одна строка JSON: размеры кадра, область, выбранный RGB, параметры, число совпадений, процент, `found` и число исключённых совпадений. Код 0 означает успешный анализ, включая `found=false`. Код 1 означает ошибку аргументов, декодирования или области; пояснение выводится в stderr.

Поддерживаются PNG/JPEG/BMP/GIF/TIFF, первый кадр, до 64 МБ и 4096×4096. Прозрачные пиксели в анализируемой области отклоняются: для проверки экранного цвета нужен непрозрачный снимок. Профили пользователя и настройки HSV здесь не загружаются.

Для проверки нужны сохранённый кадр с мишенью и несколько участков фона. RGB выбирайте из исходного пикселя мишени. Анализируйте области одинакового размера с одинаковыми параметрами и отдельно сравнивайте `found`/долю. Без разметки содержимого один результат `found=true` не доказывает правильное распознавание объекта.

## Реально проверенный файл — 18 октября 2026

Сохранённых кадров Kovaak’s в проекте не найдено. Проверено ранее предоставленное пользователем изображение 558×310 с тремя цветными обводками; это **не кадр Kovaak’s**. Файл остаётся вне репозитория. SHA-256: `4BE42C8A18D452F0E156214F81B847D9E10322E8A646D8DFAEFAE8319FF4719A`.

Выбран реальный пиксель жёлтой обводки `(465,41)`, RGB `193/198/93`. Условия: ROI 31×31, допуск 24, исключение 7×7, порог 3%.

| Область, X/Y | Совпадающие пиксели | Доля | Решение |
|---|---:|---:|---|
| Обводка, 435/25 | 40 | 4,385964912% | Совпадение |
| Фон, 518/190 | 0 | 0% | Нет совпадения |
| Фон, 375/180 | 0 | 0% | Нет совпадения |
| Фон, 191/7 | 0 | 0% | Нет совпадения |

В области обводки ещё 10 совпадающих пикселей исключены центральным квадратом. При приблизительном RGB `200/210/75` та же область дала только 5 учитываемых пикселей (0,548245614%) и не прошла порог. Это показывает влияние выбора оттенка на данном файле; цвет подбирался по этому же изображению, независимого контрольного набора нет.

Такая проверка не подтверждает работу на кадрах Kovaak’s, при движении, HDR, другом освещении или другом масштабе. Для продолжения нужны пути к реальным снимкам мишени и фона из нужного сценария.

## Автоматические проверки

`triggerlab_image_check_tests` вызывает `--self-test`: проверяет чтение BMP с путём на кириллице, BGRA/RGB, положение области и долю, границы аргументов, повреждённый/отсутствующий файл, выход области за кадр, большие координаты и прозрачность. Тест создаёт и удаляет только собственный временный каталог.

Сборка Release выполнена успешно. Общий локальный CTest: 19 проверок прошли, 3 пропущены с кодом 77 (`reference_capture`, `guided_input`, `pulse_input`) из-за фокуса/курсора; падений нет. Проверки синтетических сцен, декодирования и новой утилиты прошли. Условия предыдущей проверки 53 сцен описаны в [отдельном отчёте](color-scene-validation.md).
