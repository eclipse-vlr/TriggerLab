# Полный аудит TriggerLab — 26 октября 2026

## Результат

Проект работоспособен по проверенной сборке, но граница разрешения реальных кликов реализована непоследовательно. Главный приоритет — единая проверка допуска к вводу в расширенном и простом интерфейсах. Отдельные проблемы затрагивают диагностику запуска EXE, параллельное сохранение и восстановление незавершённого релиза.

Объект аудита: **main b3d9a6b5bca3b294f8a12aded94abd7c2286ccee**, релиз **v0.4.2**. На завершение проверки main оставался на том же SHA. Тег v0.4.2 указывает на этот коммит. Открытых PR на момент снимка нет.

Результат: **1 находка P1, 4 находки P2, 3 находки P3**. Это смесь дефектов, подтверждённых рисков и инженерного долга; она не означает восемь эксплуатируемых уязвимостей. Удалённую эксплуатацию или утечку данных аудит не установил.

## Текущее состояние

- 69 отслеживаемых файлов; 14 отдельных тестовых C++ файлов плюс встроенные GUI-проверки.
- C++20, Win32, GDI/User32, WIC; CMake/MSVC. Сторонних библиотек C++ из пакетных менеджеров в сборке не обнаружено.
- Переносимое ядро: RGB/HSV, маски цвета, геометрия, задержки, настройки, профили, диагностика и симулятор.
- Windows: захват рабочего стола, проверка полного ROI, выбор окна с PID, анализатор и отдельный тренировочный стенд.
- Настройки — в LOCALAPPDATA/TriggerLab. Кадры и эталоны рабочего режима хранятся в памяти; профили имеют отдельный формат.
- Выпуск содержит Windows x64 ZIP и SHA256. MSVC runtime собирается статически; установщик не требуется.
- Windows CI вызывает настоящий build-windows.bat и проверяет живое главное окно; Linux проверяет ядро; дополнительный Debug-прогон использует ASan/UBSan; публикация зависит от всех трёх проверок.

## A01 — P1: расширенный UI обходит обязательную проверку цвета и черновика

**Статус:** воспроизведено Windows-пробником.

[src/win32/capture_preview.cpp:1097](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L1097) разрешает autoClick при наличии running и выбранного окна. Там нет проверки colorReady, verified, settingsDirty или colorDirty. В [src/win32/capture_preview.cpp:932](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L932) также нет общей проверки этих условий перед началом реального нажатия. В простом UI проверка существует через wizardStep/guidedAction: [src/win32/capture_preview.cpp:664](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L664). Поэтому гарантия README о повторной проверке после изменения параметров не распространяется на весь интерфейс.

Воспроизведение: выбрать доступное окно → открыть «Расширенные» → снять «Проверять без кликов» → начать захват → включить триггер. Цвет можно не выбирать и не проверять. Второй путь: изменить поле на некорректный текст, затем снова включить триггер. Пробник подтвердил autoClick=true, dryRun=false и отсутствие проверки/корректного сохранённого черновика.

**Последствие:** при подходящем свежем кадре ввод может выполняться с прежним или стандартным цветом и прежними параметрами, хотя пользователь видит ещё не проверенные/ошибочные поля.

**Исправление:** единая функция допуска к реальному вводу, вызываемая при arming и перед SendInput. Для реального режима требовать выбранный цвет, проверку текущей конфигурации, отсутствие несохранённых/невалидных изменений и действующие window/PID/focus/ROI. Диагностический режим сохранить отдельно.

**Критерий:** тесты с инертным Sender запрещают реальный arming без цвета, после смены окна/профиля/HSV и при неверном черновике; нормальный проверенный сценарий остаётся работоспособным.

## A02 — P2: ошибки запуска готового EXE остаются без диагностики

**Статус:** подтверждено чтением обработчиков; отказ ресурсов/ACL на пользовательском ПК не воспроизводился.

[src/win32/capture_preview.cpp:2262](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L2262) и следующая проверка CreateWindow возвращают 1 без сообщения. Внешний catch в [src/win32/capture_preview.cpp:2290](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L2290) также молча возвращает 1. Конструктор вызывает бросающий filesystem::exists в [src/win32/capture_preview.cpp:157](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L157).

**Последствие:** ошибка доступа к данным, инициализации или ресурсам может снова выглядеть как «ничего не открылось». Исправленный BAT сохраняет сборочный журнал, но обычный пользователь запускает готовый EXE, минуя BAT. Конкретная причина прежнего пользовательского сбоя этим аудитом не установлена.

**Исправление:** ошибки RegisterClass/CreateWindow/GetMessage и исключения выводить в диалог и доступный журнал; сохранять Win32 error code и фазу запуска. Проверки существования файлов выполнять через error_code и обрабатывать отказ отдельно.

**Критерий:** принудительные отказы файловой системы и создания окна дают понятную ошибку и ненулевой код; успешный запуск не показывает лишних диалогов.

## A03 — P2: общее имя .tmp небезопасно для двух писателей

**Статус:** подтверждённый риск конкурентного пути; стресс-тест двух процессов в этом аудите не выполнялся.

Все сохранения используют одно имя path + ".tmp": [src/Config.cpp:106](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/Config.cpp#L106). Файл открывается с truncation и затем переименовывается. Уникального имени временного файла, межпроцессной блокировки или запрета второго экземпляра приложения нет.

**Последствие:** два экземпляра сохраняют одни и те же данные в LOCALAPPDATA и могут перезаписывать временный файл друг друга. Возможны ошибки сохранения и публикация данных не того писателя; в зависимости от файловой семантики — частичная/смешанная запись. Атомарное переименование само по себе не обеспечивает изоляцию писателей.

**Исправление:** уникальный временный файл в той же папке с эксклюзивным созданием; затем атомарная замена. Если два активных экземпляра не поддерживаются — mutex на экземпляр/пользователя. Политику разрешения конфликтов определить отдельно.

**Критерий:** конкурентные сохранения из двух процессов не публикуют частичные/смешанные файлы и не удаляют чужой временный файл; отказ не разрушает последний корректный файл.

## A04 — P2: повтор публикации пропускает незавершённый draft

**Статус:** подтверждено управляющим потоком workflow; отказ загрузки в настоящем релизе не вызывался.

[.github/workflows/ci.yml:153](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/.github/workflows/ci.yml#L153) завершает job при любом успешном gh release view. Позже релиз создаётся как draft, а публикуется отдельной командой: [.github/workflows/ci.yml:161](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/.github/workflows/ci.yml#L161).

**Последствие:** если draft уже создан, но загрузка assets или gh release edit завершились ошибкой, повторный job увидит этот draft и сообщит, что релиз уже существует. Job может стать зелёным, а публичного полноценного релиза не будет.

**Исправление:** различать published/draft. Для draft проверять соответствие tag/commit, комплект assets и checksum, дозагружать недостающие файлы и завершать публикацию. Готовый опубликованный релиз не перезаписывать.

**Критерий:** воспроизведение с mock gh: первый запуск падает после создания draft; второй действительно публикует ZIP и checksum, а не просто возвращает успех.

## A06 — P3: видимый «Допуск» остаётся активным в HSV, но влияет только на RGB

**Статус:** Windows-пробник подтвердил путь через реальное saveAll.

[src/win32/capture_preview.cpp:242](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/win32/capture_preview.cpp#L242) записывает значение поля в channelTolerance. HSV-сравнение использует отдельные hueTolerance/saturationTolerance/valueTolerance: [src/ColorMask.cpp:26](https://github.com/eclipse-vlr/TriggerLab/blob/b3d9a6b5bca3b294f8a12aded94abd7c2286ccee/src/ColorMask.cpp#L26). Их UI-полей нет. Подсказка существующего поля действительно говорит «RGB», поэтому ошибка касается ясности и управляемости UI, а не математической реализации HSV.

**Последствие:** после H поле «Допуск» можно менять и сохранять, но HSV-распознавание от этого не меняется. Пользователь может считать, что он настраивает активный классификатор.

**Исправление:** отключать/переименовывать RGB-поле в HSV либо показывать отдельные H/S/V-допуски с единицами и ограничениями.

**Критерий:** каждое доступное поле влияет на активный режим либо явно помечено как неприменимое; round-trip HSV остаётся точным.

## A08 — P3: монолит GUI и предупреждения затрудняют сопровождение

**Статус:** измерено по исходникам и последнему логу GCC.

capture_preview.cpp содержит 2291 строку: управление состоянием, UI, сохранение, захват, ввод и большие встроенные тесты. Изменение одного перехода состояния требует учитывать несколько разрозненных методов; A01 показывает практическое последствие. В GCC-логе есть семь предупреждений signedness/misleading-indentation в Config.cpp, AnalyzerSettings.cpp и TrainingProfile.cpp.

**Исправление:** сначала общий сервис допуска к вводу и выделение контроллера состояния, затем интерфейс хранения/захвата и перенос тестовых сценариев из production-файла. Развернуть плотные однострочные if/циклы, устранить предупреждения. Полный переписыватель GUI для этого не нужен.

**Критерий:** чистая сборка с текущим набором warnings и отдельные тесты переходов без запуска всего GUI; поведение пользователя сохраняется.

## Что уже сделано хорошо

- ClickPulse защищает общее состояние mutex, использует one-shot timer, дренирует старые callback перед повторным стартом. Отклонённый Up остаётся pending; новые Down блокируются. Закрытие главного окна не забывает незавершённое отпускание.
- Перед кликом проверяются выбранный HWND, PID, foreground, курсор и границы клиента. В режиме прицела проверяется вся область на перекрытие, включая полупрозрачные/click-through окна. Это осознанный fail-closed подход; он может блокировать безвредный оверлей.
- HoverClickGate не повторяет клик на непрерывном совпадении и не принимает большой разрыв семплов за выдержанную задержку.
- При старте dryRun=true; сохранённый профиль также загружается без включения реальных кликов.
- JSON/профили имеют ограничения размера, диапазонов, конечности чисел; отвергаются многие повреждённые/дублирующиеся/неизвестные поля. Профильное имя используется как метка с хешированным именем файла, а не как путь.
- WIC проверяет допустимые форматы, размер файла до 64 MiB и размеры до 4096×4096; COM и GDI в основных путях освобождаются через владельцев/RAII.
- В просмотренном рабочем C++ коде не найдены сетевые отправки, чтение/запись памяти чужих процессов или инжекция кода. OpenProcess используется с QUERY_LIMITED_INFORMATION для идентификации окна.
- CI по умолчанию read-only; contents:write выдан только release-job. У checkout отключено сохранение credentials. Релиз строится из прошедшего проверки SHA и содержит checksum.
- Тестовые проверки не основаны на assert, поэтому не исчезают от NDEBUG в Release.

## Дополнительное усиление и пробелы проверки

Это рекомендации, не доказательства текущей эксплуатации:

- Actions привязаны к изменяемым major-тегам v7; закрепить SHA и обновлять контролируемо.
- Артефакты не подписаны Authenticode; checksum проверяет целостность, но не подлинность издателя. Рассмотреть подпись и provenance/attestation.
- Версия дублируется в CMake и package-windows.ps1; сейчас обе 0.4.2, но проверка их равенства до упаковки отсутствует.
- Windows job работает на Server 2022. Реальные Windows 10/11, физические мониторы с разным DPI, hotplug, сон/возобновление и длительная работа требуют отдельной матрицы.
- Санитайзеры покрывают переносимое ядро на Linux. Это не проверка Win32/GDI/threadpool путей под Windows и не доказательство отсутствия всех гонок.
- Часть live-тестов допускает SKIP_RETURN_CODE=77. В проверенном выпуске пропусков нет; будущие release jobs должны явно отличать полное выполнение от допустимого пропуска.
- Функциональная совместимость с Aimlabs не установлена этим аудитом. Исторические ручные отчёты Kovaak’s не заменяют проверку текущей версии на других сценариях.
- Импорт проверен тестами в основном на BMP/PNG. Нужны дополнительные fixtures JPEG/GIF/TIFF, повреждённые/многокадровые файлы и максимальные размеры.
- Производительность не профилировалась. В горячем пути есть повторные EnumWindows и копии/выделения буферов; оптимизировать после замеров длительной сессии, а не по предположению.
- LICENSE.txt говорит, что код «остаётся закрытым», хотя репозиторий public. Уточнить намерение формулировки; публичная доступность сама по себе не даёт права менять/распространять код. Юридический аудит лицензии не проводился.
