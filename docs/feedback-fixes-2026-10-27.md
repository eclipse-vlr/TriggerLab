# Исправления по отзыву о срабатываниях и интерфейсе

## Что изменено

1. **Ранний клик у края области.** Раньше достаточная доля цвета в ROI
   разрешала срабатывание независимо от положения мишени относительно центра.
   Теперь при исключении 0 требуется совпадение центрального пикселя; при
   исключённом перекрестии — четырёх точек сразу за его границей (слева,
   справа, сверху, снизу либо всех четырёх диагональных точек). Порог покрытия сохраняется как дополнительное
   условие. Сама маска и доля цвета по всей области остаются доступны.
2. **Потеря следующей цели во время нажатия.** Захват больше не прекращается
   на время собственного Down. Успешное начало нажатия сразу фиксирует
   срабатывание, а новый свежий кадр без совпадения может повторно подготовить
   триггер даже до Up. Завершение нажатия не затирает этот переход. Новый Down
   запрещён, пока прежнее нажатие не завершено. Счётчик увеличивается только
   после принятого системой, непрерванного Up.
3. **Сброс ожидания при невысокой частоте захвата.** Предел между свежими
   совпадающими кадрами увеличен с 50 до 200 мс. Ошибка, разрыв больше 200 мс
   или обратное время начинают наблюдение заново. Сохранённые кадры не
   используются для ввода. Интервал между кликами отсчитывается после
   успешного начала предыдущего нажатия, после проверок разрешения ввода.
4. **Понятность параметров.** Рядом с восемью параметрами и RGB-допуском
   добавлены видимые «?»: назначение, диапазоны, влияние на пропуски и ранние
   клики. Поля также сохранили подсказки. Первое появление — через 400 мс,
   время чтения — до 20 секунд. Исправлена регистрация TOOLINFO для common-controls
   v5 без манифеста v6: прежняя структура с lpReserved отвергалась, и список
   инструментов подсказки оставался пустым. Теперь зарегистрировано 25 tools.

## Границы результата

Форматы настроек и профилей не менялись. Имеющиеся настройки не переписывались.
Ненулевое исключение требует видимого цвета с четырёх сторон или диагоналей: маленькая цель,
целиком закрытая исключённым центром, не сработает. Для неё нужен меньший
радиус; для видимого центрального пикселя — 0. Сдвиги X/Y должны соответствовать
реальному прицелу. Угадать цвет под непрозрачным перекрестием невозможно.

Серия тестов в собственных окнах не доказывает качество попаданий в Kovaak’s
или Aimlabs. Повтор исходного пользовательского сценария на новой сборке
остаётся необходимой ручной проверкой; исходное видео в этот чат не передано.
Смена цели, полностью произошедшая между двумя кадрами, может остаться
незамеченной. Производительность приложения здесь не профилировалась.

## Ручная проверка Kovaak’s: нулевые срабатывания

В изолированной копии пользовательских настроек несколько ручных наведений
завершились нулём диагностических срабатываний. Один ранний прогон оказался
в режиме под курсором; последующие проверены в режиме вокруг прицела. Это
не подтверждает исправление пользовательского сценария. Реальные клики
не включались. Во время подготовки наблюдалось сообщение о перекрытии ROI;
не доказано, что именно оно мешало во время ручного наведения.

Обнаружено ограничение диагностики: Stop/F9 заменял причину ожидания на
«Выключен». Добавлен сохраняемый до нового запуска итог с количеством свежих,
совпавших и недоступных кадров, максимальным покрытием и последней причиной
недоступности. Регрессия в preview smoke проверяет сохранение при Stop,
повторном Stop и сброс при новом запуске. Сохранённые данные не участвуют
в разрешении ввода. Изменены capture_preview.cpp, PreviewTests.inl, README.md
и CHANGELOG.md.

После добавления итога Release-сборка прошла. Полный CTest: 28/28, без
пропусков, 89,25 с; лог `build-release/live-diagnostics-ctest.log`.
`git diff --check` прошёл; все пять сохранённых хешей личных файлов совпали.
Ранний запуск smoke по ошибке пересёкся с линковкой и заблокировал замену EXE
(LNK1104); тот результат старого EXE не учитывается. После завершения smoke
сборка повторена успешно, затем выполнен указанный полный прогон новой сборки.

## Исправление длинного перекрестия после ручной проверки

Реальный итог Kovaak’s: 179 свежих кадров, 0 недоступных, максимальное покрытие
88%, 0 совпадений центра. На экране прицел в форме белого плюса находился
внутри жёлтой мишени. Лучи плюса закрывали кардинальные точки за исключённым
квадратом. Это дефект предыдущего условия центрирования, а не доказательство
неисправности захвата или неверного RGB.

Добавлен альтернативный набор из четырёх диагональных точек на том же отступе.
Все четыре точки одного набора должны совпасть: одна сторона цели по-прежнему
не разрешает ввод. Условие центрального пикселя при ignore_radius=0 сохранено.
Регрессия длинного плюса сначала воспроизвела отказ старого условия; добавлены
проверки края цели и диагонального перекрестия. Личные параметры не менялись.

Release-сборка прошла; узкие analyzer/color_scene/color_click — 3/3.
Полный CTest — 27 пройдено, 1 пропущен из-за смены фокуса/физического ввода,
133,90 с (`build-release/crosshair-fix-ctest.log`). Пропущенный target_sequence
затем отдельно прошёл за 2,41 с. `git diff --check` прошёл; основной EXE и
CapturePreview имеют одинаковый SHA256.

Проверка исправленного EXE в Kovaak’s на копии актуальных личных параметров:
1 диагностическое срабатывание, 0 реальных кликов, 924 свежих кадра,
28 совпадений центра, максимальное покрытие 84%. 1429 недоступных отсчётов
включают подготовку с перекрывающим оверлеем инструмента и переключения фокуса;
оверлей снят сбросом сессии управления перед успешным распознаванием. F9
остановил анализатор, итог сохранён, появилась кнопка «Включить клики».
Все пять личных файлов совпали по хешам с копией до теста. Серия реальных
попаданий в игре этим прогоном не проверялась.
